# Stage 2: Android app (Capacitor) and web viewer

## What it is

- `app/www/`: the viewer (plain HTML/CSS/JS, no build step). Korean UI, mint/teal palette.
  - (0.4.0) Chart picker by level x product, forecast-hour grid with download state, background prefetch,
  WPSH overlay on every chart of the same domain, info sheet, light/dark theme.
- Chart tabs, run selector, forecast-hour slider / step buttons / play, pinch-zoom (double tap: 2.5x).
  - WPSH red line toggle on 500 hPa charts (00/12Z runs only; 06/18Z shows why there is no line).
  - **Past-run comparison**: for the current chart and valid time, plays every run that has that frame,
    oldest to newest; the newest run is highlighted; labels show the run time and H-50 on 500 hPa.
  - Help sections collapsed by default; attribution + link to NOTICE.
- Data: `index.json` and images from Cloudflare R2 (`DATA_BASE` in `app.js`, since Stage 3; see
  docs/STAGE3.md). `?data=<url>` overrides it in a browser.
  `?data=<url>` overrides it (local testing). `index.json` is fetched with a cache-busting query.
- `app/android/`: Capacitor 8 Android project (`appId io.github.brownie3748cell.ecmwfviewer`,
  name "ECMWF 뷰어"). Back button closes the comparison sheet first; the manifest is reloaded on resume.
- Icons/splash: `python app/tools/make_icons.py` (run from `app/`) redraws them.

## Builds (`.github/workflows/android.yml`)

| trigger | result |
|---|---|
| push to a branch / PR touching `app/` | debug APK artifact `ecmwf-viewer-debug-apk` (30 days) |
| main → Run workflow, tick **release** | signed release APK, published as a GitHub Release `v<version>-<run>` |

`versionName` = `app/package.json` version, `versionCode` = workflow run number.

The web viewer is published with the site by `publish.yml` (`--app-dir app/www`) at `<site>/app/`.

## Signing key (owner action, once)

The keystore is created by the owner on their own computer and stored only in repository secrets.
It is never generated by the pipeline and never committed.

1. Create the keystore (needs a JDK; Android Studio also has a wizard: Build > Generate Signed App Bundle/APK):
   `keytool -genkeypair -v -keystore ecmwf-viewer.jks -keyalg RSA -keysize 2048 -validity 10000 -alias ecmwfviewer`
2. Base64-encode it.
   Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("ecmwf-viewer.jks")) | Set-Content ks.txt`
   macOS/Linux: `base64 -w0 ecmwf-viewer.jks > ks.txt` (macOS: `base64 -i ecmwf-viewer.jks -o ks.txt`)
3. Repository → Settings → Secrets and variables → Actions → New repository secret:

| secret | value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | contents of `ks.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | keystore password |
| `ANDROID_KEY_ALIAS` | `ecmwfviewer` (or the alias you chose) |
| `ANDROID_KEY_PASSWORD` | key password |

4. Delete `ks.txt`. Keep `ecmwf-viewer.jks` and its passwords backed up privately: an installed app can only
   be updated with an APK signed by the same key.
